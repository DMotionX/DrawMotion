# Contributing to DrawMotion

Thank you for your interest in improving DrawMotion. This guide explains how to contribute code, bug reports, and ideas, and what we expect from contributions.

## Ways to Contribute

- Report bugs
- Suggest features or improvements
- Fix bugs or implement features
- Improve documentation and translations
- Test pre-release builds and share feedback

## Before You Start

1. Check the existing issues and pull requests to make sure your idea or bug has not already been reported or fixed.
2. For anything larger than a small fix, open an issue first and describe what you want to change. This avoids duplicated effort and wasted work.
3. Read the README for how to build and run the project locally.

## Reporting Bugs

Open an issue and include:

- A clear, short title
- Steps to reproduce the problem
- What you expected to happen and what actually happened
- Your app version and Windows version
- Screenshots, a screen recording, or a sample project file if possible

## Suggesting Features

Open an issue that explains the problem you want to solve, not only the solution. Describe who benefits and give examples of how it would be used.

## Submitting Code

1. **Fork** the repository and create a branch from `main`. Use a descriptive name, such as `fix/export-crash` or `feature/layer-groups`.
2. **Keep changes focused.** One pull request should address one issue or feature. Avoid unrelated formatting or refactoring changes.
3. **Follow the existing code style** and structure of the project. Use clear names and add comments where the intent is not obvious.
4. **Test your changes.** Make sure the app builds and runs, existing features still work, and you have verified the change manually or with tests where they exist.
5. **Write clear commit messages.** Use a short summary line in the imperative (for example, "Fix crash when exporting empty project"), followed by details if needed.
6. **Open a pull request** against `main` and fill in the description:
   - What the change does and why
   - The issue it relates to (for example, `Closes #123`)
   - How you tested it
   - Screenshots or recordings for UI changes

## Review Process

- A maintainer will review your pull request and may ask for changes.
- Reviews focus on correctness, quality, maintainability, performance, and fit with the project's direction.
- Please respond to feedback and update your branch. Pull requests with no activity for a long time may be closed, and can be reopened later.
- Maintainers have the final decision on what is merged.

## Licensing and Ownership

- DrawMotion is released under the **GNU General Public License v3.0 (GPLv3)**. By submitting a contribution, you agree that it will be licensed under the same license.
- Only submit work that you wrote yourself or that you have the right to submit under a compatible license.
- Do not remove or change license headers or attribution notices.
- If you add third-party libraries, fonts, images, icons, or audio, state their source and license in the pull request. They must be compatible with GPLv3.

## Content Guidelines

Everything added to the project, including code, comments, commit messages, documentation, and sample assets, should be professional and suitable for a general audience. Please avoid offensive, explicit, or deceptive content, and any code that is malicious or collects data without clear disclosure.

## Communication

- Keep discussions focused on the project and its technical details.
- Be respectful and constructive. Critique the work, not the person.
- Politics, religion, and other off-topic debates are not for project spaces.
- Be patient. Maintainers and contributors are often volunteers.

If someone's behavior is disrupting the project, please report it privately to `conduct@easysoft.dev`. Maintainers may edit or remove comments and contributions, and may limit participation, when needed to keep the project productive.

## Questions

If something here is unclear, open an issue with your question and we will help.
